# e-Palette ONE：生成AI・交通標準連携 v1.2

この版は、同一のWebアプリに接続口と本人確認を実装した、合成データによる検証版です。外部AI、交通事業者、QR認証ハブ、実車への接続は未実施です。本番MVPの完成や国土交通省の認定を示しません。既存の「横のエレベーター」の試験結果は流用していません。

## 共通業務処理

2026-09-26追加：ログイン不要の `/`・`/connections` は、同じ業務規則をブラウザー内だけで使う合成データ体験です。外部AIと同じ運用台帳を使うのは、認証された `/workspace`・`/workspace/connections` です。体験データや `/try/approvals/*` のローカル確定を、サーバーの本人承認へ昇格・同期しません。

通常画面の `/api/commands` と、通常API・MCP・A2A・COMmmmONSは `lib/model.ts` の同じ業務規則、D1の同じworkspace状態を使用します。連携の乗車予約は既存ticketを作成し、既存画面からの乗降・取消もその状態に反映されます。旅客の予約はticket、事業者の車両確保はbooking、未配車の乗車依頼はrideです。物販・清掃・充電・引継ぎを交通予約へ変換しません。

D1には所有者ごとのworkspace、操作receipt、audit、期限付き委任キーを保存します。全経路の更新は同じ楽観ロックと原子的batchを使用します。再送キーが同一なら同じ業務結果を返し、異なる入力へのキー再利用は拒否します。返す状態は最新なので、確定後の取消などがあれば現在の状態が返ります。

## 本人が確定する流れ

1. `prepare_*` が具体的な変更案を保存。対象便・乗降点・日時・人数・金額・操作内容、依頼者、役割、作成時点の状態バージョンを固定します。まだ空席確保・課金・配車はしません。
2. 返された `approvalUrl` を同じ本人が開き、内容を確認します。10分で期限切れ。別人、異なるCSRF、更新された状態、期限切れは拒否します。
3. 「この便を予約する」「この予約を取り消す」など、操作を明記したボタンで承認と業務処理を同じD1更新内で保存。担当者への依頼を作っても、車両・充電器へ指令は出しません。
4. APIやAIは `get_proposal` で結果を取得できます。`execute_approved` の再送でも二重処理しません。クライアント指定の `approved: true` は無効です。

画面操作は大きな文字、64px以上の主ボタンを使用。主な確認内容をまとめ、確定は1回の操作です。取消案にも本人確認が必要です。全workspaceの更新で承認案を失効させる保守的な方式のため、無関係な予定の変更でも再確認が必要になる場合があります。保存期限や高齢者の実操作試験を含む本番運用評価は未実施です。

## 接続口

| 経路 | 実装した内容 | 残る条件 |
|---|---|---|
| `/api/v1/actions/{name}` | 検索・状況・充電計算・予約案・承認済み実行など13操作 | 本番データ、役割・組織管理の実運用 |
| `/mcp` | MCP 2026-07-28のstateless HTTP。discover/list/call | 対象AIの接続、認証方式、互換性試験 |
| `/.well-known/agent-card.json`、`/a2a` | A2A v1.0 JSONRPCのSendMessage/GetTask/CancelTask | 外部エージェントとの試験 |
| `/commmmons/v1/...` | デマンドバス1.0.0の10操作。原本の入出力スキーマ検証 | 残り9操作、仮予約、相手先の必須プロファイル |
| `/api/v1/gtfs` | 同じ予定からSchedule ZIP出力。ZIPの限定検査 | JP v4全項目検査、配信更新運用、外部取込 |
| `/api/v1/gtfs/realtime` | データ未接続として503 | 許可された動的運行情報とRealtime生成 |
| `/commmmons/qr/notify-authenticated-ticket` | 相手先未設定として503。単回乗車通知の内部変換をローカル試験 | 権利登録・発券・認証ハブ・永続台帳・精算 |

通常APIの定義は `api/openapi.json`、MCPツール定義は `api/mcp-tools.json`、A2Aは `api/a2a-agent-card.json` と `api/a2a-task-data.schema.json` を参照。実装から `pnpm run spec:export` で生成します。

## 認証・権限

Web画面はホスト提供の本人認証を使用し、所有者ごとにD1データを分離します。Web専用APIはBearerでの利用を拒否します。委任キーは本人が `/api/v1/credentials` で自分に対して発行する検証用機能で、passenger/driver/managerを指定し、有効期限24時間、DBには秘密部分のハッシュのみ保存します。発行・解除を監査に記録します。キーに承認権限はありません。driverは参照のみ、passengerは自分の乗車予約、車両・充電・運行管理操作はmanagerのみです。

ログイン不要の体験のため、公開入口には本人認証を要求しません。保存用管理画面・業務API・承認APIには引き続き本人認証、または許可された委任キーを要求します。開発環境の認証省略も廃止しました。OAuth認可サーバー、対象AI登録、実組織の役割付与は未実装・未検証です。公開URLがあるだけで、外部AIが接続済みとは扱わないでください。端末内の体験予約は外部AIへ公開しません。

## MCP利用契約

`POST /mcp` のみ。`Content-Type: application/json`、`Accept: application/json, text/event-stream`、`MCP-Protocol-Version: 2026-07-28`、`Mcp-Method` を指定します。呼出時には `Mcp-Name` も一致させます。毎回の `params._meta` に `io.modelcontextprotocol/protocolVersion` と `io.modelcontextprotocol/clientCapabilities` を付けます。旧版のinitialize/session方式は実装していません。

変更案・承認済み実行には引数 `requestId` と同じ値の `Mcp-Param-Request-Id` を付け、再送時も保持してください。通常APIでは `Idempotency-Key` を使います。業務上の失敗は `isError: true`。未定義機能・入力やヘッダーの不一致はプロトコルエラーです。許可されないツールは一覧にも表示しません。

## A2A利用契約

`A2A-Version: 1.0` と認証を付けます。JSONRPCの大文字メソッド名を使用し、messageのroleは `ROLE_USER`。対応する入力は単一のDataPartです。`data: {name, args}` を送り、name/argsは通常APIと共通です。自由文を実行命令として解釈しません。

messageIdは再送で保持します。検索・計算は `TASK_STATE_COMPLETED`、確認が必要な変更案は `TASK_STATE_INPUT_REQUIRED` を返します。本人の確定後、GetTaskで結果を得られます。対象taskId/contextIdを使った承認済み再開も可能です。同一IDで内容を変更した依頼は拒否します。取消は未承認の依頼のみに許可し、確定済み乗車予約の取消は別の本人確認付き変更案を使用します。ストリーミングとpush通知はadvertiseしていません。

## 交通標準の採用範囲

デマンドバスの候補検索・予約確定・本人予約一覧・取消を採用。合成サービス `mdl-demo-fixed-stops`、大分駅前→地域拠点、配車済みの2点間便、一般区分 `demo-general`、無料運行に限定します。未配車、車いす設備未設定、未定義の区分や予約変更を成功扱いにしません。候補は仮予約ではなく、在庫確保や有効期限保証はありません。COMmmmONS経由の書込みには通常APIで作成し本人が確認したproposalを `X-Proposal-ID` で指定します。元の標準に加えた、このアプリ固有の認証・承認契約であり、未改修の全事業者との互換性は保証しません。

Scheduleは明示された停留所・運行日時から作成。日付をまたぐ便は24時以降の時刻を保持します。地名・座標・運賃は検証用で、公式停留所データや実運行ではありません。Flexは明示的な時間帯を渡した変換関数と試験のみです。固定時刻から都合のよい運行区域・窓を推測して公開しません。Realtimeは取得元未設定で、合成位置から実車遅延を作りません。

QR内部変換は、登録した相手先と利用権利の対応、同一通知の再送、内容改変、使用済み権利を検査する単回entryの試験です。外部HTTP口は無効で、契約なしに認証成功や乗車済みへ変更しません。JSONスキーマ通過は共通QR発券・認証ハブ接続の完了を意味しません。

## 本番MVPの未完了ゲート

正式な車両状態の提供契約・実車試験、対象AIとOAuth等の接続、事業者の採用プロファイル合意・相互接続、JP v4検証と配信、QR権利・発券・精算の永続処理、実組織の権限、65歳以上を含む実操作評価が必要です。担当は連携開発責任者、交通事業者窓口、運行管理責任者、UX検証担当で分担し、接続の証跡・日時・仕様版・制約を `standards/connections.json` に追記します。具体的な相手先・担当者名は未指定です。


## v1.2：サービス照会と予約取消

`get_service_catalog` はUIと同じ車両予定からサービス、指定乗降点、予約条件、明示された日付の営業時間を返します。通常API、MCP、A2Aで同じ結果を返し、認証・readスコープを要求します。定時の2点間便を扱うため `fixed_time_fixed_route` とし、高度なオンデマンド配車を提供すると装いません。

COMmmmONSの `getTerms`、`getServices`、`getServicesId`、`getPassengersIdServices`、`getStops`、`getReservationsIdPayment` を追加しました。クエリも原本スキーマから静的生成した検査で確認します。検索項目間はAND、一覧は既定で開始前・実施中、詳細のみoperation_settings等を含みます。週間運行を推測せず、登録済み日付と24時以降の時間を保持します。

停留所の位置条件は経度,緯度の順、半径はメートル、既定500mです。名前検索はnameのみを対象とし、かな・search_wordsへ暗黙拡張しません。利用者別の照会と支払状態は本人だけが参照できます。無料予約は `excluded`、取消後は `cancelled`。実決済がないのに `received` を返しません。未設定の有料状態は503です。

`getTerms` は同意不要の検証用案内だけを返します。本番の法的規約・同意記録を代替せず、未設定の規約カテゴリは空配列です。サービスはprivateで、実運行も外部接続もありません。

「あなたの乗車予約」→「取消内容を確認」→「この予約を取り消す」の2操作で取消。最初の操作では予約・空席を変えず、確認後に共通DBを更新します。乗車時刻を過ぎた本人取消は受け付けず、運行担当者の状態確認を求めます。既存管理画面の担当者操作とは区別します。
