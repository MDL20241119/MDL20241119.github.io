# e-Palette ONE — 管理者Webアプリ実装メモ

更新: 2026-09-25 / 車両連携前提のMVP・機能検証版

## 動く範囲

- 今日・予定・車両・その他の4画面。スマートフォンの下部メニュー、大きな主要ボタン。
- 車両ごとの残量、位置名、距離、充電状態、取得元と時刻。模擬データを常時明示。
- 次の利用の必要電力と、普通／急速の充電時間、移動・接続・確認を含む期限の逆算。
- 予定の登録・取消、車両と担当者の重複検証、開始前確認、開始・返却申請・受領・貸出可能の分離。
- オンデマンドの指定乗降点受付、候補検証、手動確定。
- 乗車予約・区間別人数検証・乗車・降車の記録。QR読取は未実装。
- 商品在庫・受注・受付停止・準備・受取・取消、支払確認と返金確認を分離。オンライン決済はなし。
- 引継ぎの依頼・受領・担当変更・完了。外部への通知はなし。
- 障害報告・使用保留、復旧根拠、操作履歴、予定CSV。
- D1への永続保存。冪等性キー、楽観ロック、原子的な状態更新・監査記録。
- 認証された利用者ごとのデータ分離。現状は各利用者専用の管理者検証環境。

## 本番MVPに到達していない条件

この版を実車運行に使用しない。車両連携がMVPの必須条件であることは変更していない。
実車未接続のため、本番MVPの受入は未完了である。

1. 接続先固有の認証・SDK・Webhook変換、車両別の同意・データ利用契約。
2. 実車ごとのSOC定義・利用可能電力量・AC/DC特性・受入制限・誤差の実測較正。
3. 複数組織のメンバー管理・役割別権限・担当者本人による受領。
4. 運転者・物販担当者・乗客専用の認証画面。現在は管理者が業務を記録する。
5. 外部通知・充電設備の空き確認・外部予約・遠隔開始・実決済。
6. 正式な安全確認項目・点呼・資格証憑・記録保存期間、障害時運用。
7. 実車の一日連続運用・高齢者8〜12名の操作試験・WCAG 2.2 AA適合検証。
8. 継続監視・復旧・バックアップ試験・性能SLA。現時点では達成値を主張しない。

## 操作の設計

- 定型予約は「予定をつくる → この予定を確定」の2タップ。別テンプレートの選択を加えて3タップ（変更なし・競合なしの場合）。
- 充電はホームの「充電の予定を確認 → この充電を担当者に依頼」の2タップ（既定条件が適合する場合）。
- 日時・車両などの編集欄は必要なときだけ開く。
- 主要ボタンは64 CSS px、本文・操作文字は原則18px以上。状態は文字と色で示す。
- 保存結果は消える通知だけに頼らず、閉じるまで画面に表示する。
- 必須の安全確認は各項目を未実施から記録し、包括承認で短縮しない。

## データと計算

`lib/model.ts`は状態遷移・充電計算の中心。Vehicle、Booking、Session、Task、Ticket、Ride、Orderは別のIDで関連付ける。
初期対象1〜3台の機能検証を想定し、D1の利用者別ワークスペースにJSONスナップショットで保存する。更新版を条件に、状態・冪等性記録・監査を同じトランザクションで確定する。本番の組織共同運用前に組織メンバーと各データのアクセス範囲を設計する。

充電テスト用の利用可能容量60kWh、電費0.42kWh/km、補給への移動10km、予備8kWh等は架空の仮定。メーカーの実車性能値ではない。表示SOCは車両別の対応表へ置き換える必要がある。
ACは実効上限と効率、DCはSOC帯ごとの受入制限・共有出力・実電力を使う。古いSOC・中断・不適合・必要残量100％超は成立させない。

## API

- `GET /api/state`: 自分の検証状態。匿名は401。開発プレビューだけローカル模擬ユーザーを許可。
- `POST /api/commands`: 業務の状態変更。Idempotency-KeyとexpectedVersion必須。
- `GET /api/export`: 自分の予定CSV。表計算式として解釈されるセルをエスケープ。
- `POST /api/integrations/vehicle`: 実車未接続時は503で拒否。
- `lib/vehicle-adapter.ts`: 正規化イベント、既知車両照合、重複・遅着・未来時刻の検出。ベンダー固有アダプターは未実装。

VCIや走行・扉・鍵・車高の遠隔制御APIは持たない。
