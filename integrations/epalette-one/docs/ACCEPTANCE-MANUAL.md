# 現MVPの手動観測受入

原AT-01〜22とINT-01〜20は別セットとして保持する。42のIDは42件合格済みの意味ではない。原ATの自動車両取得条件は、現MVPでは以下の手動観測条件へ読み替える。

| ID | 現MVPの条件 | ローカル証跡 | 外部／現場 |
|---|---|---|---|
| AT-01-M | 残量・観測時刻・確認者と現場状態を記録し、充電・次利用判定へ反映 | manual-soc / MVP-02,04 | 実車確認待ち |
| AT-02-M | 実時計の陳腐化、利用・充電後の失効、未観測を利用可へ変換しない | MVP-03,06,17 | 現場期限の確定待ち |
| AT-03 | 競合する確定を防ぐ | MVP-10,11 / API-06 / SQLite | 実D1・端末同時操作待ち |
| AT-04 | 二重操作・応答消失の再送で二重確定しない | API-05 / manual-journal | 実通信復旧待ち |
| AT-05 | 車両QRを本人認証に使わず、認証・所属・貸出権限を検証 | API-01,03,04 / MVP-09 | QR識別画面・実端末試験待ち |
| AT-06 | 運行日時点の資格期限を検証 | 既存domain / MVP-02 | 資格証憑・現場確認待ち |
| AT-07 | 必須安全確認なしに利用開始を確定しない | 既存domain / MVP-02,14 | 実務チェック内容の確認待ち |

| AT-09-M | プラグ接続と完了を分け、充電後の手入力・解除を要求 | manual-soc / MVP-05,16 | 通電・終了の現場手順確認待ち |
| AT-10-M | 出力・待ち時間の変更で必要時間と間に合う見込みを再計算 | 既存domain / MVP-16 | 低出力報告・連絡を含む現場検証待ち |

| AT-13 | 次用途の準備時間を含め競合を防ぐ | MVP-10,11,23 / 既存domain | 地域別所要時間の確認待ち |
| AT-14 | 各区間の乗車人数上限を守る | 既存domain | 実内装・乗降試験待ち |
| AT-15 | 在庫と受取枠を超える注文を拒否 | MVP-22 / API-06 / 既存domain | 実決済・返金は未接続 |
| AT-16 | 未降車・未受取を残したまま次利用可能にしない | MVP-05,13,14 | 現場手順確認待ち |
| AT-17 | 異常の影響予約と権限・復旧根拠を記録 | MVP-15,25 / MVP-09 | 実車復旧と責任者の確認待ち |

| AT-19 | 組織を越えるデータ・CSV取得をサーバー側で拒否 | API-03,04,07 / MVP-18 | 実D1・複数アカウント・端末試験待ち。写真共有は未実装 |

追加診断AUD-01〜06への対応：SOC以外の現場入力、担当本人／理由付き代理、最終貸出判定、体験と実業務の分離、実時計評価、匿名台帳の統合を実装。課題の再現成功を「受入合格」と数えない。

採用規格とINT-01〜20の原対応は `standards/CONFORMANCE.md`。今回のローカル試験に外部接続の証跡を混ぜない。実車制御や未承認の外部送信・決済を実行しない。


UI/UXの追加受入（原AT番号と混同しない）：UX-01〜04で最初の3つの入口、4メニュー、予約手順、現場入力の意味構造をReactのサーバー描画で確認。実機200％拡大・キーボード通し操作・読み上げ・高齢者試験は未実施。
