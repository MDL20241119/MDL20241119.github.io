# 大分未来モビリティ・コンソーシアム 立上げ管理

タスク・日程・判断事項を共同管理するフルスタックアプリのソースです。GitHub Pagesに実行アプリや入口リンクを掲載する構成ではありません。関係者用URLは別途共有し、サーバー側の共通パスワードで保護します。

## 構成

- React / Vinext：画面、週間予定、発足までの工程、タスク詳細・編集
- Cloudflare Worker互換のAPI：認証・権限チェック・更新競合の検出
- D1：タスク、履歴、管理者、共有認証設定、期限付きセッション
- 共通パスワードの関係者：タスクと予定の閲覧・編集
- 管理者：信頼されたChatGPT認証のuser IDと既存members行で判定。本人用根拠と共有設定は管理者限定

実データ、初期データseed、本人用根拠、メール本文、認証情報、セッション、公開URL、実行環境の識別子はこのリポジトリに含めません。実行中の既存DBを再作成・初期化しないでください。発足日は認証後にDBの節目レコード（M-09）から取得します。

## ローカル起動

Node.js 22.13以上を使用します。

1. npm ci
2. npm run check
3. npm run build
4. dist/server/wrangler.json を使い、drizzle/*.sql を順番にローカルDBへ適用
5. ローカル検証に限り tests/setup-local.sql を適用
6. npm run dev（開発用ログイン）または npm start（ビルド済Worker）

ローカルD1への適用例：

    node --import ./scripts/sites-env.mjs ./node_modules/wrangler/bin/wrangler.js d1 execute DB --local --config dist/server/wrangler.json --persist-to .wrangler/state --file drizzle/0000_wise_william_stryker.sql

0001のマイグレーションも同様に一度だけ適用します。テスト用ownerは本番へ入れません。共有認証のAPI回帰テストはローカルの5174番ポートに対して node tests/shared-auth.cjs で実行できます。テストは毎回架空の一時パスワードを生成し、終了時に共有ログインを停止します。

## パスワードと共有

- パスワードは管理者が /admin/sharing に自分で入力、確認、登録します。チャット、ソース、環境例、ログには書きません。
- サーバーにはランダムsaltとscrypt検証値のみ保存。N=32768、r=8、p=3、32バイト出力、maxmem=64MiB。
- 共有セッションはランダムな256-bit値。DBにはSHA-256ダイジェストのみ保存し、ブラウザーにはSecure・HttpOnly・SameSite=Strict・host-only cookieを設定。
- 共有セッションは最長6時間、リクエストがない状態で2時間。共有PW変更・停止で既存セッションは無効化。
- 同一originのJSONと、共有編集時のCSRFトークンを検証。入力サイズをストリーム段階で制限。
- ログインは全体と信頼された送信元情報の範囲で試行制限。送信元IPの意味は実ホスティング経路で確認し、個人単位の制限と誤認しないこと。
- 共通PWでは個別本人の識別や個別の利用停止はできません。履歴には「共有メンバー」と記録します。
- 短いものも受け付ける互換要件がありますが、推測されにくい長いパスワードを強く推奨します。

## 既存環境への再配信

1. 変更後に型チェック、入力検証、認証回帰テストを実施する。
2. .openai/hosting.example.json からローカル設定を作り、管理者が確認した既存プロジェクトIDを設定する。同じDBのDBバインディングを維持する。
3. npm run build で dist/server/index.js と dist/client を生成する。スキーマ変更時は npm run db:generate でSQLを追加し、適用済みのマイグレーションを書き換えない。
4. ソースの正確なコミットと対応するビルドを、既存Sitesプロジェクトの保存・発行機能で配信する。新しい別プロジェクトや空DBを自動作成しない。
5. まず本人限定のまま未認証API拒否、共有editorの管理者拒否、内部根拠の非開示、保存・競合、失効、レート制限を確認する。
6. 本人が共有PWを設定したあと、明示承認された公開入口方式へ変更する。PWゲートの前にタスクデータを出さない。
7. 実画面と実APIの検証を行い、失敗時は直前のソース・同じDBを使って復旧する。DBをリセットしない。

サイトへの入口リンク追加、公開範囲の変更、実際のPW設定はコード更新とは別の操作です。明示的に許可された範囲だけで実施してください。

## 安全なソース管理

このディレクトリは機密データを含まないソースのスナップショットです。以前の私有開発履歴やDBファイルを公開Git履歴へ取り込まないでください。.env、.wrangler、.sites-runtime、node_modules、dist、本番owner情報はコミット対象外です。
