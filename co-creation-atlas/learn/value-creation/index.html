START FROM IMPLEMENTATION / 社会実装から考える

社会実装から逆算して、入口を設計する。

ここで重視するのは、実証ができたかだけではありません。実際の利用者・業務・地域の中で使われ、担当者・費用・運営・責任が引き受けられる状態から逆算します。次の6つは、事例を読むためのMDLの確認軸です。

  1. 誰が、何のために使うか

    受益者と導入判断者を分ける。導入部門、生活者、現場担当者を課題設定から巻き込み、使われる場面と変更可能な範囲を決める。

  2. 誰が、どう購入・採用するか

    実証契約と本導入を分ける。購買・予算責任者、公共調達、社内承認、地域の合意形成へ進む条件を先に確かめる。

  3. 日常の条件で動くか

    性能だけでなく、既存設備・データ・人員・利用ルールとの適合を試す。例外、停止時の代替手段、安全、参加者の負担も検証する。

  4. 終了後の運営と費用は誰が担うか

    実証費と継続費を分ける。保守、教育、問い合わせ、苦情、データ更新の引受先と財源を、実証中から設計する。

  5. 何が変われば、続けてよいか

    試作品や契約だけでなく、利用・負担・費用・暮らしの変化を確かめる。改善前、比較対象、期間、測定者、変更・停止の条件を置く。

  6. 誰に、何を引き渡すか

    技術に加えて、使う権利、運用手順、技能、責任を渡す。別地域では条件を再確認する。同じ地域で無理なく定着することも実装の出口。

これは、最後の07・08だけの仕事ではありません。導入条件から必要なインプットを選び、01の課題設定、03の仲間づくり、06の現場検証にも織り込みます。8工程を順番に消化するのではなく、実装を妨げる条件が分かれば上流へ戻ります。

各事例の「社会実装から逆算した工夫」は公開資料にある仕組みを読み解いたものです。原典が意図を明記しない場合は「MDLの分析」と表示し、こちらの提案を事例の実績として扱いません。具体的な実装事例は案件と時点を限定し、仕組みがあることと成果が出たことを分けます。

インプットは、5つに分ける。

人的資本
自社・運営主体、他社、行政、スタートアップ、アカデミア。それぞれの人が持つ専門性と、担当する仕事。住民・利用者が参加する場合は、生活の知識や経験も含めます。
有形資産
場所、建物、試作機、実験装置、測定機器。持っているだけでなく、誰がどの条件で使えるかを確認します。
関係資本
人や組織の間にある、信頼、協力関係、ネットワーク、継続的な対話や連携の仕組み。参加者の数やロゴの数だけでは測れません。
金融資本
何に使える、誰のお金か。施設整備、日々の運営、個別案件の実証、導入後の運用を分けます。補助金の終了後にも使える財源があるかを確認します。
課題
誰の、どんな困りごとや挑戦か。課題を持つ人、解決の判断者、現場の制約も入口で明確にします。「新しい施設をつくる」は手段であり、課題そのものではありません。

この5分類は本サイトの編集枠組みです。課題は資本と同じものではありませんが、価値創造の出発点としてインプットに置きます。必要な事例では、知的・データ資産（知財、データ、ソフトウェア、ノウハウ）を別に補足します。

人的資本と関係資本は、重なっても同じではない。

「行政の担当者が現場の利用調整をする」は人的資本の役割。「行政と企業が、継続して実証案件を受け渡せる」は関係資本です。資金提供だけが確認できる場合、実務を担う人の参加まで推定しません。

8工程は、価値創造機能の中にある。

課題を捉え、未来を問い、仲間をつくり、デジタルや現物で試し、現場で確かめ、事業にし、社会へ広げる。これらは資源を使って価値を生むための働きです。事業化や横展開を行ったというだけで、望ましいアウトカムが生まれたとは限りません。

「つくった」と「変わった」を分ける。

ILLUSTRATIVE / 説明のための仮例

インプット
利用者、現場担当者、開発者、試験場所、実証費、使いにくい受付という課題。
価値創造機能
受付を観察し、利用者と案を作り、模擬運用と現場試験で改善する。
アウトプット
受付の試作品、運用手順書、検証記録、導入に関する合意。
アウトカム
待ち時間や職員負担が減り、利用者が手続きを完了できるようになる。実際に起きたかは、導入前後の測定などで確かめる。

受注や導入は、設定した分析単位によって直接成果にも、初期の事業上の変化にもなります。このサイトでは対象と時点を示し、売上・利益・生活改善・地域への波及へ自動的に読み替えません。

報告された変化は、因果効果の証明ではない。

いつ、誰を、何と比べ、何を測ったのか。他の投資や景気、参加者の選ばれ方、現場の負担も確認します。分からないことは「未確認」、将来の効果は「目指す変化」と表示します。結果をもとに、インプットや価値創造機能を見直すところまでが学びです。
