横の
エレベーター

まちを、エレベーターのように。

スマホや電話で呼ぶと、地域を走る普通のクルマが迎えに来る。買い物、通院、地域の集まりなど、日常の「ちょっとそこまで」を支える呼び出し型モビリティです。

本ページは導入事例・仕組みの紹介です。現在の運行状況や利用条件を案内するものではありません。

00 / CONCEPT

専用車両をつくるのではなく、
地域にあるクルマを使いやすくする。

縦のエレベーターが「呼ぶ → 来る → 行きたい階へ」を実現するように、横のエレベーターは「呼ぶ → 来る → 行きたい場所へ」を実現します。大切なのは車両そのものではなく、利用者・ドライバー・管理者を一つの仕組みでつなぐことです。

USER

利用者

LINEや電話から、乗る場所・降りる場所を選びます。

  • 地図から選ぶ
  • 人数を入力
  • 車両到着を確認
DRIVER

ドライバー

届いた依頼を受け、アプリが示す順番に迎えに行きます。

  • 依頼を受ける
  • 最適順に巡回
  • 到着・乗降を記録
ADMIN

管理者

運行状況と実績をリアルタイムに把握します。

  • 車両位置
  • 待ち時間・件数
  • 日報・月報・分析
01 / USER

利用者は、4ステップ。

STEP 01

乗る場所

地図から乗降ポイントを選びます。

STEP 02

降りる場所

買い物先など目的地を選びます。

STEP 03

人数・確認

人数と内容を確認し、呼び出します。

STEP 04

乗車

到着案内を確認し、車両に乗ります。

スマホだけにしない。

実証ではLINEに加え、電話受付も用意しました。デジタル操作への慣れに応じて入口を選べる設計です。

「使える人だけが使えるサービス」にしないことも、地域モビリティの重要な設計要件です。

02 / DRIVER

ドライバーは、依頼を受けて、
順番どおりに走る。

1. 呼び出しを受ける

優先度の高い依頼が「処理待ち」に表示され、引き受けると「運行確定」に移ります。

2. 巡回順を確認

引き受けた依頼は、最適な巡回順に自動で並び替え。左から順に運行します。

3. 到着を知らせる

乗車場所に着いたら「到着通知」。利用者が見当たらない場合や満車の場合も画面から処理できます。

4. 降車を記録する

目的地に到着し、利用者が降りたことを確認して「降車」を押すと1件が完了します。

03 / ADMIN

管理者は、運行を
リアルタイムで見る。

稼働表示

車両位置、呼び出し状況、乗車人数、キャンセル、走行距離、速度、ドライバー情報を確認。

運行KPI

平均待ち時間、平均乗車時間、最大・最小時間など、サービス品質を把握。

日報・月報

車両データ、時間データ、時間帯別件数、乗降場所別件数を日次・月次で確認。

改善に使う

どこで、いつ、どれだけ使われたかを見て、停留所・時間帯・車両配置・運行方法を改善します。
