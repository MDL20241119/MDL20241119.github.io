START / はじめに

まちを、
エレベーターのように。

スマホで呼ぶ。近くの乗降場所で待つ。普通のクルマに乗る。行きたい場所へ移動する。

呼ぶ → 待つ → 乗る

専用の特殊車両ではなく、一般的な乗用車を地域の移動に活用する考え方です。

MOBILITY DESIGN LAB
01 ユーザー用
HOW TO / 基本操作

はじめてでも、
この4ステップ。

  1. 乗る場所を選ぶ

    地図上の乗降ポイントから、現在地に近い場所を選びます。

  2. 降りる場所を選ぶ

    買い物先、公民館など、行きたい場所に近い乗降ポイントを選びます。

  3. 人数を確認して「OK」

    出発・到着・乗車人数を確認して依頼します。

  4. 呼び出し完了を確認

    車両が確定したら通知を確認し、指定された乗降場所で待ちます。

地域が案内するLINEを友だち追加

利用入口は地域ごとの運用に従います。実証ではLINEと電話受付を用意したケースがあります。

MOBILITY DESIGN LAB
01 ユーザー用
BEFORE YOU GO / 利用前の確認

出かける前に、
ここだけ確認。

車が来る前に、何をすればよい？

アプリの案内を確認し、指定した乗降場所で待ちます。

呼び出した後、乗らなくなったら？

地域の運用ルールに従い、キャンセルまたは連絡を行います。

スマートフォンの操作が難しいときは？

電話受付などを用意する場合があります。地域の案内を確認してください。

車いすや大きな荷物は載せられる？

車両や運行条件によって異なります。事前に地域の運営窓口へ確認してください。

この地域のご利用案内

運行日・時間／対象者／料金／電話番号／LINE登録先は、導入地域ごとに設定します。

START / 運行開始

安全な一便を、
迷わずつなぐ。

02

ドライバーを選ぶ

自身のアカウント・担当を確認します。

03

車両を選ぶ

当日使用する車両を選択してログインします。

出発前に、車両・スマホ・通信・連絡先を確認。
MOBILITY DESIGN LAB
02 ドライバー用
FLOW / 基本操作

呼び出しから降車まで、
この順番で。

  1. 呼び出しを引き受ける

    処理待ちの依頼を確認し、担当する呼び出しを引き受けます。

  2. 表示の順序を確認する

    乗車場所と降車場所、巡回順を確認して安全に移動します。

  3. 着いたら「到着通知」

    利用者に到着を知らせます。停車位置と周囲の安全を確認します。

  4. 降りたことを見て「降車」

    利用者の降車を目視確認してから、画面上の処理を完了します。

MOBILITY DESIGN LAB
02 ドライバー用
EXCEPTION / 例外対応

困ったときは、
状況で押し分ける。

「到着通知」

指定場所へ到着し、利用者を迎えられる状態になったとき。

「乗せられない」

満車や車両条件など、利用者を乗せられない場合。

「乗せる人がいない」

指定場所に到着しても利用者が確認できない場合。

勝手に完了扱いにしない。

停留所・車両・依頼内容を再確認し、運営ルールに従って処理します。

MOBILITY DESIGN LAB
02 ドライバー用
CHECK / 運行前後

始める前と、終わる前。
確認を習慣にする。

出発前

車両／燃料・充電／スマホ／通信／ログイン／当日の運行エリア／緊急連絡先を確認。

終了前

処理待ちの依頼が残っていないか、乗車中の利用者がいないか、日報・車両状態を確認。

「受付」は全体。「処理待ち」は優先して対応する依頼。

MOBILITY DESIGN LAB
03 管理者用
DASHBOARD / 状況確認

いまの状況を、
3つの視点で確かめる。

いまの待ち

現在の待ち状況を確認。

今日の実績

引き受け件数や利用状況を確認。

車両ごと

オーダー、乗車人数、稼働状態を確認。

「いまの待ち」と「今日の実績」を分けて見る。

MOBILITY DESIGN LAB
03 管理者用
IMPROVE / 運用へのつなげ方

数を集めて終わらず、
次の運行を良くする。

01

待ち時間が長い

時間帯・車両配置・乗降場所・運行手順のどこに原因があるか確認します。

02

キャンセルが多い

満車、不在、操作ミスなどを分け、案内や待機ルールを見直します。

03

利用が少ない

「知らない」「使えない」「行き先が合わない」を聞き分けます。

運行と責任

責任者／運行体制／乗降場所／対象者／日時／料金／休止判断

連絡と例外対応

利用者窓口／満車・不在・障害・緊急時の対応

データと権限

閲覧者／保存・共有範囲／個人情報／報告方法

本番環境の確認

アプリ提供版／端末・通信／担当者教育／テスト運行

「何人乗ったか」の先も、別に記録する。

買い物や通院を実現できたか。外出が増えたか。運営費を誰が負担し、続けられるか。数字と現場の声を合わせて改善します。
